Безопасный ассистент для VibeCoding и анализа данных, вдохновлённый китайским мифическим зверем Байцзэ.

**Открытый Coding Agent CLI с мощной защитой конфиденциальности и многоязычным взаимодействием. Поддерживает несколько бэкендов (DeepSeek / OpenAI-совместимые / Zhipu / Qwen / Kimi / локальный Ollama) и предоставляет полный набор возможностей: вызов инструментов, загрузку навыков, делегирование субагентам, сжатие контекста, безопасную песочницу и многое другое.**

----------

# Ключевые преимущества

## Защита конфиденциальности

- **Двусторонняя обратимая защита конфиденциальности**: конфиденциальная информация заменяется плейсхолдерами перед отправкой в LLM и автоматически восстанавливается после получения ответа. Весь процесс незаметен для пользователя: история, параметры инструментов и итоговые ответы, которые вы видите, всегда остаются исходным текстом, а LLM видит только случайные непредсказуемые плейсхолдеры вроде `«PZ_PHONE_a3f8b2c1d4e5f6a7»`.
- **Полное маскирование на диске**: файлы сессий, сжатые транскрипты и журналы аудита автоматически маскируются перед записью на диск (включено по умолчанию). Открытые PII никогда не появляются на диске.
- **Устойчивость к инъекциям**: плейсхолдеры используют 64-битные криптографические случайные токены, которые невозможно перебрать, подделать или воспроизвести. Старые плейсхолдеры становятся недействительными сразу после смены сессии.
- **Несколько способов включить защиту конфиденциальности**: можно включить режим защиты конфиденциальности, введя естественный язык в командной строке, или использовать более точную команду `/privacy`.
- **Локальный агент**: продукт не имеет удалённой базы данных и работает полностью локально. Он не собирает информацию о пользователе.

## Многоязычное взаимодействие

- **Поддержка девяти языков**: китайский, English, 日本語, 한국어, Español, Français, deutsch, русский, العربية.
- **Несколько способов переключения языка**: можно напрямую написать `please speak with english`, чтобы переключиться на английский, или использовать `/lang ja` для переключения на японский.

# Возможности

- **Поддержка нескольких бэкендов**: DeepSeek, любой OpenAI-совместимый endpoint (GLM / Qwen / Kimi / OpenAI) и локальный Ollama. Переключение одним кликом.

- **Запуск без настройки**: при первом запуске автоматически создаются файлы конфигурации. Пользователю достаточно один раз указать ключ.

- **Маскирование конфиденциальности**: перед отправкой в LLM автоматически распознаёт и маскирует **более 30 категорий** конфиденциальной информации (телефоны, email, удостоверения личности, паспорта, банковские карты, международные номера, API-ключи, JWT, строки подключения к базам данных, MAC-адреса и т. д.), а после получения ответа автоматически восстанавливает их. **Маскирование также применяется при записи на диск**, не оставляя открытого текста. Поддерживает два уровня: стандартный / строгий, переключаемые естественным языком или `/privacy`.

- **Многоязычное взаимодействие**: свободно переключайтесь между китайским / английским / японским / корейским / испанским / французским / немецким / русским / арабским. Достаточно сказать `English` или ввести `/lang ja`, и ИИ будет думать и отвечать на соответствующем языке в течение всей сессии.

- **Полная цепочка инструментов**: выполнение bash, чтение/запись/редактирование файлов, поиск glob/grep, веб-поиск и загрузка страниц, фоновые задачи, управление задачами и todo.

- **Система навыков (Skills)**: загрузка предметных знаний (SKILL.md) по требованию, что делает ИИ более профессиональным в特定 сценариях.

- **Субагенты (Subagents)**: делегирование сложных задач субагентам с независимым контекстом, чтобы не загрязнять основную сессию.

- **Хуки (Hooks)**: хуки на Python или Shell. Поддерживают перехват до/после вызова инструментов, журналы аудита, автоматическое форматирование и контроль тестов.

- **Протокол MCP**: подключение внешних серверов инструментов через Model Context Protocol (GitHub, Filesystem и т. д.).

- **Сжатие контекста**: двухуровневое сжатие (усечение результатов инструментов + суммаризация LLM). Поддерживает сверхдлинные диалоги.

- **Безопасная песочница**: белый список команд, обнаружение выхода за пределы пути, перехват опасных команд, защита конфиденциальных файлов и перехват инъекций скриптов.

- **CLI в чёрно-золотой теме**: адаптивная ширина для китайского, подсветка кода, раскраска diff и сворачивание размышлений.

# Установка

## Предварительные требования

- Python 3.10+ (требуется tomllib, встроен в 3.11+; для 3.10 установите tomli)

- pip

## Установка из исходников

### Два способа загрузки

1. `pip install https://github.com/Xu123-Bob/Baize.git`

    bash -- Нажмите Win+R, введите `cmd`, затем введите:

    baize

2. На странице репозитория нажмите `<> Code` --> `Download ZIP`

(1) После распаковки перейдите в каталог этого файла:

    bash -- Нажмите Win+R и введите cmd

    cd каталог-после-распаковки

    pip install -r requirements.txt

    python -m Baize

После установки нажмите Win+R, введите cmd, чтобы открыть CLI, и введите `baize` для запуска.

(2) Скачайте ZIP и установите локально. После распаковки перейдите в каталог и выполните:

    bash -- Нажмите Win+R и введите cmd

    pip install .

После установки нажмите Win+R, введите cmd, чтобы открыть CLI, и введите `baize` для запуска.

### Опционально: установка зависимостей для подключения данных (важные инструменты анализа данных)

Если вы хотите, чтобы Baize управлял SPSS или базами данных SQL, установите дополнительные зависимости:

```bash
pip install -r requirements-data.txt
```

`requirements-data.txt` содержит:
- `spss-studio-mcp`: MCP-сервер статистического анализа SPSS (требуется локально установленный IBM SPSS Statistics)
- `atengk-mcp-server-rdbms`: MCP-сервер универсальных реляционных баз данных (PostgreSQL / MySQL / SQL Server / Oracle / DM и т. д.)
- `pyodbc`: Python-привязка ODBC, необходимая для SQL Server

Альтернативно, если проект установлен через `pyproject.toml`, можно использовать extras:

```bash
pip install -e ".[data]"          # Установить все зависимости подключения данных сразу
pip install -e ".[spss]"          # Установить только SPSS
pip install -e ".[sql]"           # Установить только универсальный SQL
pip install -e ".[sql-mssql]"     # Только SQL Server (включая pyodbc)
```

- **⚠️ Пользователям SQL Server: `pyodbc` — это только Python-привязка. Также необходимо установить Microsoft ODBC Driver 18 for SQL Server на уровне системы.**
- **⚠️ Пользователям SPSS: `spss-studio-mcp` — это только мост MCP. IBM SPSS Statistics (версия 20–31) должен быть уже установлен локально и иметь действующую лицензию, а переменная окружения `SPSS_INSTALL_PATH` должна указывать на каталог установки SPSS. В настоящее время движок SPSS в основном поддерживает полный анализ в Windows; в Linux/macOS он может перейти в «файловый режим» (чтение файлов .sav, просмотр метаданных, предпросмотр данных, но без статистического анализа).**

# Быстрый старт

1. Первый запуск

```bash
baize
```

При первом запуске Baize автоматически создаёт два файла конфигурации:

```
~/.baize/config.toml   # Конфигурация бэкенда (выберите DeepSeek / OpenAI / Ollama)
~/.baize/.env          # Файл ключей
```

В Windows путь: `C:\Users\ВашеИмяПользователя\.baize\`.

2. Выбор бэкенда

Откройте `~/.baize/config.toml` и измените **active_provider** (обязательно):

```toml
# Файл конфигурации Baize
# Измените active_provider для переключения бэкенда  # Возможные значения: "deepseek" / "qwen" / "kimi" / "glm" / "openai" / "ollama"

active_provider = "deepseek"

[model_providers.deepseek]
name = "DeepSeek"
base_url = "https://api.deepseek.com"
env_key = "DEEPSEEK_API_KEY"
model = "deepseek-flash"

[model_providers.qwen]
name = "Qwen"
base_url = "https://dashscope.aliyuncs.com/compatible-mode/v1"
env_key = "DASHSCOPE_API_KEY"
model = "qwen-plus"

[model_providers.kimi]
name = "Kimi"
base_url = "https://api.moonshot.cn/v1"
env_key = "MOONSHOT_API_KEY"
model = "kimi-k2.7-code"

[model_providers.glm]
name = "GLM"
base_url = "https://open.bigmodel.cn/api/paas/v4"
env_key = "ZHIPUAI_API_KEY"
model = "glm-4-plus"

[model_providers.openai]
name = "OpenAI"
base_url = "https://api.openai.com/v1"
env_key = "OPENAI_API_KEY"
model = "gpt-4o"

[model_providers.ollama]
name = "Ollama (локальный)"
base_url = "http://localhost:11434/v1"
env_key = ""
model = "qwen2.5:7b"
```

3. Ввод ключа

Отредактируйте `~/.baize/.env`. **Если нужно использовать определённую LLM, удалите `# ` в начале соответствующей строки, а перед другими LLM добавьте `# `, чтобы заблокировать их вывод API. После ввода API Key обязательно сохраните файл; изменения вступят в силу только после сохранения**:

```env
# ============================================================
# Файл ключей Baize
# ============================================================
# Заполняйте только ключ используемого бэкенда, остальные оставьте закомментированными.
# Имена переменных должны совпадать с полем env_key в config.toml.
#
# Расположение:
#   Linux / macOS: ~/.baize/.env
#   Windows:       C:\Users\ВашеИмяПользователя\.baize\.env
# ============================================================

# ---------- DeepSeek (бэкенд по умолчанию) ----------
# Получить: https://platform.deepseek.com/api_keys
DEEPSEEK_API_KEY=

# ---------- OpenAI или любой OpenAI-совместимый endpoint (опционально) ----------
# Подходит для Groq, Qwen, Moonshot, Zhipu, OpenAI и т. д.
# Примечание: base_url настраивается в config.toml в [model_providers.xxx], не здесь
# OPENAI_API_KEY=

# ---------- Qwen (опционально) ----------
# Получить: https://dashscope.console.aliyun.com/
# DASHSCOPE_API_KEY=

# ---------- Kimi / Moonshot (опционально) ----------
# Получить: https://platform.moonshot.cn/console/api-keys
# MOONSHOT_API_KEY=

# ---------- Zhipu GLM (опционально) ----------
# Получить: https://open.bigmodel.cn/usercenter/apikeys
# ZHIPUAI_API_KEY=

# ---------- Пользовательский шлюз (опционально) ----------
# CUSTOM_API_KEY=

# ---------- Ollama (локальная модель, ключ не нужен) ----------
# Достаточно убедиться, что Ollama работает на localhost:11434. Здесь ничего настраивать не нужно.
```

4. Перезапуск

```bash
baize
```

Если вы видите чёрно-золотой логотип и приветственное сообщение, запуск успешен.

## Многоязычное взаимодействие

Baize поддерживает **девять языков**: китайский, English, 日本語, 한국어, Español, Français, deutsch, русский, العربية.

Есть два способа переключения:

### Способ 1: просто говорить (автоопределение)

Baize автоматически определяет язык ввода и переключается:

```
>>> 降旨：Hello, help me write a Python script
[Система] Обнаружен язык ввода: English. Baize переключился на взаимодействие на English.
(Baize отвечает на английском)

>>> 降旨：日本語で答えてください
[Система] Обнаружен язык ввода: 日本語. Baize переключился на взаимодействие на 日本語.
(Baize отвечает на японском)
```

### Способ 2: ручная команда

```
>>> 降旨：/lang                # Показать текущий язык и доступный список
[Система] Текущий язык: китайский (zh)
[Система] Доступные языки:
    zh    中文 ←
    en    English
    ja    日本語
    ko    한국어
    es    Español
    fr    Français

>>> 降旨：/lang English        # Переключить по названию языка
>>> 降旨：/lang ja             # Переключить по коду языка
>>> 降旨：/lang 西班牙语        # Названия на китайском тоже поддерживаются
```

Поддерживаются четыре формы: **название языка / код языка / китайское название / родное название**. Например, для переключения на английский подойдёт любое из `English`, `en`, `英语`, `英文`.

## Встроенные команды

- `/exit, /quit` --> Выйти из Baize
- `/clear` --> Очистить историю диалога, todo, записи размышлений и записи инструментов
- `/compact` --> Вручную сжать контекст (используйте, когда диалог слишком длинный)
- `/commit` --> Сохранить текущую сессию и сделать commit в Git (если внутри Git-репозитория)
- `/lang` --> Показать текущий язык; `/lang en` переключает на английский (поддерживает код или название языка)
- `/skills` --> Показать все доступные навыки
- `/skills reload` --> Перезагрузить каталог пользовательских навыков
- `/unload` --> Выгрузить текущий активный навык
- `/show thought` --> Показать полную запись размышлений
- `/show tool` --> Показать записи вызовов инструментов
- `/show all` --> Показать всю историю сессии
- `/技能名` --> Загрузить указанный навык (поддерживается нечёткое сопоставление)
- `/privacy` --> Управление маскированием конфиденциальности (on / off / strict / status / rules / test / clear)
- `/privacy rule-off <name>` --> Отключить правило маскирования (например, `/privacy rule-off phone_intl`)
- `/privacy rule-on  <name>` --> Снова включить правило

# Локальные модели Ollama (нулевая стоимость)

Не хотите использовать облачный API? Используйте локальный Ollama:

```bash
# 1. Установите Ollama: https://ollama.com/download
# 2. Загрузите модель
ollama pull qwen2.5:7b

# 3. Запустите сервис Ollama
ollama serve

# 4. Измените ~/.baize/config.toml
active_provider = "ollama"

# 5. Запустите Baize
baize
```

Рекомендуемые модели: `qwen2.5:7b` (сильна в китайском), `llama3.1:8b`, `deepseek-r1:7b`.

# Механизмы расширения

Baize поддерживает четыре способа расширения. Достаточно разместить их в текущем рабочем каталоге, и они вступят в силу.

## Навыки (Skills)

Пишите предметные знания в `./skills/имя-навыка/SKILL.md`. ИИ будет проактивно загружать их при сложных задачах.

```markdown
---
name: pandas-eda
description: Лучшие практики исследовательского анализа данных с pandas
tags: data,python
---
```

## Хуки (Hooks)

Разместите в `./hooks/`:

- `PreToolUse-*.sh`
- `PostToolUse-*.sh`
- `Stop-*.sh`

Они получают JSON на входе и возвращают решение:

```bash
#!/bin/bash

read -r input

if echo "$input" | grep -q "rm -rf"; then
  echo '{"hookSpecificOutput":{"permissionDecision":"block","permissionDecisionReason":"Deletion prohibited"}}'
```


# Безопасность (ядро)

Baize по умолчанию включает следующие механизмы безопасности:

- **Белый список команд**: разрешены только обычные команды вроде `ls`, `cat`, `grep`, `git`, `python3` и т. п.
- **Обнаружение выхода за пределы пути**: все файловые операции ограничены текущим рабочим каталогом и `/tmp`.
- **Перехват опасных команд**: перехватываются шаблоны `rm -rf /`, fork bomb, `curl | sh`, `git push --force` и т. п.
- **Защита конфиденциальных файлов**: запрещено изменять `.env`, `.ssh/`, `id_rsa`, `*.pem` и т. п.
- **Перехват инъекций скриптов**: обнаруживаются обходы вроде `python -c "os.system(...)"`.
- **Ограничения ресурсов процессов**: в Linux/macOS ограничиваются CPU, память и число процессов.
- **Маскирование конфиденциальности (двустороннее обратимое)**: PII заменяются случайными плейсхолдерами на выходе и восстанавливаются на входе; независимое маскирование при записи на диск.
- **Устойчивость к инъекциям плейсхолдеров**: 64-битные криптографические случайные токены + нейтрализация на стороне ввода + изоляция сессий.
- **Маскирование журналов аудита**: `hook_audit_log` маскирует перед записью на диск + усекает + отказывается писать при ошибке.

Если нужно ослабить ограничения в доверенных проектах, можно изменить `ALLOWED_COMMANDS` и `FORBIDDEN_PATH_PATTERNS` в `Baize.py`.

# Маскирование конфиденциальности (ядро)

Baize имеет встроенный механизм **двустороннего обратимого маскирования + маскирования на диске**, покрывающий весь путь от ввода до диска:

- **Исходящее**: перед отправкой в LLM PII заменяются на непредсказуемые плейсхолдеры
- **Входящее**: плейсхолдеры в ответах LLM восстанавливаются в исходный текст
- **На диске**: файлы сессий, сжатые транскрипты и журналы аудита **независимо маскируются** перед записью. На диске не остаётся открытого текста

**По умолчанию отключено**, включайте при необходимости.

## Два способа включения

### Способ 1: естественный язык

Скажите прямо в диалоге:

```
>>> 降旨：Включи маскирование конфиденциальности
[Система] Маскирование конфиденциальности включено (стандартный режим).

>>> 降旨：Включи строгое маскирование
[Система] Маскирование конфиденциальности включено (строгий режим).

>>> 降旨：Отключи защиту конфиденциальности
[Система] Маскирование конфиденциальности отключено.
```

### Способ 2: слэш-команды

- `/privacy on` Включить стандартный режим
- `/privacy strict` Включить строгий режим
- `/privacy off` Отключить
- `/privacy status` Показать статус, ID сессии, число правил, статистику LRU/TTL
- `/privacy rules` Показать все правила (включая статус включения)
- `/privacy rule-off <name>` Отключить правило
- `/privacy rule-on  <name>` Снова включить правило
- `/privacy test <text>` Проверить эффект маскирования
- `/privacy clear` Очистить сопоставление плейсхолдеров и **сменить ID сессии**

## Два уровня

**Стандартный**: номера мобильных Китая, номера удостоверений личности, номера банковских карт (проверка Luhn), email, IPv4/IPv6, API-ключи OpenAI/Anthropic/GitHub/AWS, Bearer Token, блоки приватных ключей, поля паролей, учётные данные в URL.

**Строгий**: всё из стандартного + китайские имена, номера QQ, ID WeChat, номера автомобилей Китая.

## Как это работает

Ввод пользователя (с реальными PII) → messages хранит исходный текст

↓ `sanitize_messages()`

В LLM отправляется `[[PHONE_1]]`, `[[EMAIL_1]]`

↓ Ответ LLM

Возвращённые плейсхолдеры → `restore_message()`

Восстанавливаются в исходный текст → запись на диск / отображение / выполнение инструментов

- **Маскирование конфиденциальности (двустороннее обратимое)**: PII заменяются случайными плейсхолдерами на выходе и восстанавливаются на входе; независимое маскирование при записи на диск.
- **Устойчивость к инъекциям плейсхолдеров**: 64-битные криптографические случайные токены + нейтрализация на стороне ввода + изоляция сессий.
- **Маскирование журналов аудита**: `hook_audit_log` маскирует перед записью на диск + усекает + отказывается писать при ошибке.

## Умная градация параметров инструментов

**Маскируются** (чисто текстовые параметры, не участвующие в реальном выполнении):
- `todo`, `ask_user_question`, `task_create`, `task_update`

**Не маскируются** (пути/команды/URL реально используются):
- `run_read` / `run_write` / `run_edit` / `run_glob` / `run_grep` (пути используются для IO)
- `run_bash` / `background_run` (команды выполняются)
- `run_webfetch` / `web_search` (URL реально отправляются в сеть)
- `set_workspace` (путь используется для `chdir`)
- `load_skills` (имена навыков — это перечисления)
- `agent` (контекст субагента маскируется независимо)
- `mcp_*` (неизвестная семантика, консервативная обработка)

**При сохранении на диск маскируется всё** (поскольку сохранённое содержимое не будет повторно исполнено; безопасность важнее).

## Маскирование на диске

**Включено по умолчанию**, независимо от маскирования в памяти. Даже если использовать `/privacy off` (без маскирования в памяти), маскирование на диске всё равно применяет как минимум стандартные правила.

**Ключевые особенности**:
- Маскирование на диске использует **независимую одноразовую таблицу сопоставления** — плейсхолдеры, записанные на диск, **невозможно восстановить**, так как таблица сопоставления отбрасывается
- Если маскирование на диске **не удалось, запись открытого текста отклоняется** (без деградации, без тихого пропуска)
- Если старые файлы сессий содержат открытый текст, при первом сохранении они автоматически маскируются и перезаписываются

**Как отключить** (не рекомендуется): измените `PERSIST_REDACT_ENABLED = False` в `Baize.py`.

# Подключение данных (ядро)

Baize подключается к корпоративному ПО для анализа данных через **MCP (Model Context Protocol)**. Основная программа не требует изменений — достаточно зарегистрировать сервер в `MCP/mcp_config.json`.

## Подключение SPSS

### Предварительные условия

- Локально установлен IBM SPSS Statistics (версия 20–31; рекомендуется Windows)
- SPSS имеет лицензию и нормально запускается

### Шаги настройки

1. **Найдите каталог установки SPSS:** путь по умолчанию обычно `C:\Program Files\IBM\SPSS Statistics\` с номером версии (например, 31).

2. **Задайте переменную окружения** (можно в `.env` или системных переменных):

```text
SPSS_INSTALL_PATH=C:\Program Files\IBM\SPSS Statistics\31
```

3. **Проверьте статус**:

```bash
spss-studio-mcp status
```

Ожидаемый вывод:

```text
=== SPSS MCP Capability Status ===
pyreadstat : OK v1.3.6
pandas     : OK v3.0.2
SPSS batch : OK
```

4. **Зарегистрируйте в `MCP/mcp_config.json`**:

```json
{
  "mcpServers": [
    {
      "name": "spss",
      "command": "spss-studio-mcp",
      "args": ["serve", "--transport", "stdio"],
      "env": {
        "SPSS_INSTALL_PATH": "C:\\Program Files\\IBM\\SPSS Statistics\\31"
      },
      "enabled": true
    }
  ]
}
```

### Если `SPSS batch: NOT FOUND`

Это означает, что `spss-studio-mcp` не нашёл движок SPSS, но `pyreadstat` + `pandas` работают. В этом случае включается **файловый режим**:

- Можно читать `.sav`, просматривать метаданные, предпросматривать данные и конвертировать CSV ↔ SAV
- Нельзя запускать статистику (t-тест, регрессия, ANOVA и т. д.)

Решение: правильно задайте `SPSS_INSTALL_PATH` в `MCP/mcp_config.json` или примите переход в файловый режим.

## Подключение SQL

### Поддерживаемые базы данных

PostgreSQL, MySQL, MariaDB, SQL Server, Oracle, DM, KingbaseES, TiDB, OceanBase и т. д. (на основе драйверов SQLAlchemy 2.0).

### Шаги настройки

1. **Подготовьте read-only учётную запись базы данных** (настоятельно рекомендуется):

```sql
CREATE USER baize_ro WITH PASSWORD 'xxx';
GRANT SELECT ON ALL TABLES IN SCHEMA public TO baize_ro;
```

2. **Подготовьте строку подключения**:

- PostgreSQL --> `postgresql+psycopg://user:pwd@host:5432/db`
- MySQL --> `mysql+pymysql://user:pwd@host:3306/db`
- SQL Server --> `mssql+pyodbc://user:pwd@host:1433/db?driver=ODBC+Driver+18+for+SQL+Server`
- Oracle --> `oracle+oracledb://user:pwd@host:1521/?service_name=ORCL`

3. **Зарегистрируйте в `MCP/mcp_config.json`**:

```json
{
  "mcpServers": [
    {
      "name": "sql",
      "command": "atengk-mcp-server-rdbms",
      "args": ["--transport", "stdio"],
      "env": {
        "DATABASE_URL": "postgresql+psycopg://baize_ro:pwd@localhost:5432/prod"
      },
      "enabled": true
    }
  ]
}
```

### Защитные механизмы (встроенные)

`atengk-mcp-server-rdbms` обеспечивает несколько уровней защиты:

- **SELECT-защита на уровне AST**: анализирует синтаксическое дерево с помощью `sqlglot` и физически блокирует операции записи вроде `DELETE/UPDATE/DROP/TRUNCATE`.
- **Автоматическая подстановка LIMIT**: запросы без указанного числа строк принудительно получают `LIMIT 100`, предотвращая переполнение памяти при полном сканировании таблицы.
- **Read-only по умолчанию**: операции записи должны быть явно разрешены через `--allow-dml` / `--allow-ddl`.
- **Перехват SQL-инъекций**: на уровне AST отклоняются вредоносные инструкции, построенные конкатенацией строк.

### Настройка нескольких баз данных одновременно

Если нужно подключиться к нескольким базам одновременно, зарегистрируйте несколько серверов:

```json
{
  "mcpServers": [
    {
      "name": "sql_prod",
      "command": "atengk-mcp-server-rdbms",
      "args": ["--transport", "stdio"],
      "env": { "DATABASE_URL": "postgresql+psycopg://ro:pwd@prod:5432/db" },
      "enabled": true
    },
    {
      "name": "sql_warehouse",
      "command": "atengk-mcp-server-rdbms",
      "args": ["--transport", "stdio"],
      "env": { "DATABASE_URL": "mysql+pymysql://ro:pwd@dw:3306/analytics" },
      "enabled": true
    }
  ]
}
```

Baize автоматически объединит все их инструменты в `MATERTOOLS`, и LLM будет выбирать автоматически по задаче.

# Разработка

## Запуск тестов

Проект использует pytest. Перед разработкой установите пакет в редактируемом режиме с зависимостями разработки:

```bash
pip install -e ".[dev]"
```

Запустить все тесты:

```bash
python -m pytest tests/ -v
```

Запустить один файл:

```bash
python -m pytest tests/test_history.py -v
```

## Соглашения о структуре кода

- `agent/`: основной пакет, публикуемый с пакетом. Вся runtime-логика и ресурсы (skills, subagent, hooks, MCP) находятся здесь.
- `agent/core/`: модули чистой логики без внешних побочных эффектов. **Они должны тестироваться отдельно.** Добавляйте такую логику сюда и сопровождайте тестами.
- `tests/`: соответствие один-к-одному с исходными файлами в `agent/`, имена `test_<модуль>.py`.
- Любая функция с внешними зависимостями (сеть, диск, глобальное состояние) должна внедрять зависимости через параметры, чтобы их можно было подменять в тестах.

# ❓ Часто задаваемые вопросы

- В: Куда вводить ключ?

О: В `~/.baize/.env`, а не в `.env` в корне проекта.

- В: Нужно ли переустанавливать при смене бэкенда?

О: Нет. Просто измените `active_provider` в `~/.baize/config.toml`.

- В: Нужен ли ключ для локального Ollama?

О: Нет. Выберите `active_provider = "ollama"` и оставьте `env_key` пустым.

- В: Как сменить рабочий каталог?

О: В диалоге просто скажите «переключись на /path/to/project», и Baize вызовет инструмент `set_workspace`.

- В: Что будет, если контекст слишком длинный?

О: Baize автоматически выполняет двухуровневое сжатие: сначала усекает старые результаты инструментов, затем просит LLM сгенерировать сводку. Также можно вручную использовать `/compact`.

- В: Может ли он случайно удалить мои файлы?

О: Белый список команд по умолчанию перехватывает опасные операции вроде `rm -rf /`; перед записью файла показывается Diff и запрашивается подтверждение.

- В: Как подключить Baize к SPSS?

О: 1. Установите `pip install -r requirements-data.txt`; 2. задайте переменную окружения `SPSS_INSTALL_PATH` на каталог установки SPSS; 3. включите сервер spss в `MCP/mcp_config.json`. Подробнее см. раздел «Подключение данных (SPSS / SQL)».

- В: Что делать при `SPSS batch: NOT FOUND`?

О: Это означает, что движок SPSS не найден. Проверьте, указывает ли `SPSS_INSTALL_PATH` на каталог с `stats.exe`; если вы работаете только с `.sav`, можно игнорировать это предупреждение (будет файловый режим).

- В: Что ещё нужно установить для подключения к базе SQL?

О: На уровне Python установите `atengk-mcp-server-rdbms` (`pip install` сделает это автоматически). **Пользователям SQL Server также нужно установить Microsoft ODBC Driver 18 на уровне системы**, это нельзя установить через pip.

- В: Может ли Baize случайно удалить данные моей базы?

О: Нет. SQL MCP по умолчанию разрешает только SELECT и блокирует все операции записи на уровне AST. Всё равно настоятельно рекомендуется создать отдельную **read-only учётную запись базы данных** для Baize как двойную защиту.

- В: Утекут ли данные из результатов анализа SPSS в LLM?

О: Если маскирование конфиденциальности включено (`/privacy on`), результаты инструментов автоматически маскируют PII вроде телефонов, email и удостоверений личности перед отправкой в LLM. **Но рекомендуется также использовать read-only учётную запись + выборку данных** (запрашивать только необходимые поля), чтобы снизить риск.

- В: Почему после добавления SPSS/SQL каждый диалог Baize стал медленнее и использует больше токенов?

О: Потому что определения инструментов, предоставляемые MCP-серверами, отправляются в LLM на каждом раунде диалога. У SPSS более 60 инструментов, что добавляет около 6 000–12 000 токенов фиксированных накладных расходов. Если ваш обычный рабочий процесс не связан со SPSS, можно установить `enabled` в `false` и включать при необходимости.
