Помощник по безопасности для Vibe Coding и анализа данных, вдохновлённый китайским мифическим зверем.

**Открытый Coding Agent CLI с мощной защитой конфиденциальности и многоязычным взаимодействием. Поддерживает несколько бэкендов (DeepSeek / совместимые с OpenAI / Zhipu / Tongyi / Kimi / локальный Ollama) и предоставляет полный набор возможностей: вызов инструментов, загрузку навыков, делегирование субагентам, сжатие контекста и безопасную песочницу.**

----------

# Ключевые преимущества

## Защита конфиденциальности

- **Двунаправленная обратимая защита конфиденциальности**: Конфиденциальная информация заменяется заполнителями перед отправкой в LLM и автоматически восстанавливается после получения ответа. Весь процесс невидим для пользователя: история, параметры инструментов и окончательные ответы, которые вы видите, всегда содержат исходный текст, а LLM всегда видит случайные, непредсказуемые заполнители, такие как `«PZ_PHONE_a3f8b2c1d4e5f6a7»`.
- **Полное маскирование на диске**: Файлы сессий, сжатые транскрипты и журналы аудита автоматически маскируются перед записью на диск (включено по умолчанию). Открытые PII никогда не появляются на диске.
- **Устойчивость к инъекциям**: Заполнители используют 64-битные криптографические случайные токены и не могут быть перечислены, подделаны или воспроизведены. Старые заполнители немедленно становятся недействительными после смены сессии.
- **Несколько способов включить защиту конфиденциальности**: Вы можете включить её через естественный язык в CLI или использовать более точную команду `/privacy`.
- **Локальный агент**: Данный продукт не имеет удалённой базы данных и работает полностью локально. Он не собирает информацию о пользователях.

# Возможности

- **Поддержка нескольких бэкендов**: DeepSeek, любой совместимый с OpenAI эндпоинт (GLM / Qwen / Kimi / OpenAI) и локальный Ollama. Переключение одной настройкой.

- **Запуск без настройки**: Файлы конфигурации создаются автоматически при первом запуске. Пользователю нужно ввести API-ключ только один раз.

- **Маскирование конфиденциальности**: Автоматически определяет и маскирует **более 30 типов** конфиденциальной информации перед отправкой в LLM (номера телефонов, электронные почты, удостоверения личности, паспорта, банковские карты, международные номера, API-ключи, JWT, строки подключения к базам данных, MAC-адреса и т. д.) и восстанавливает их после получения ответа. **То же маскирование применяется при записи на диск**, поэтому открытый текст не остаётся на диске. Поддерживает стандартный и строгий режимы, переключаемые через естественный язык или команду `/privacy`.

- **Многоязычное взаимодействие**: Свободно переключайтесь между девятью языками: китайский, английский, японский, корейский, испанский, французский, немецкий, русский и арабский. Скажите `English` или используйте `/lang ja`, и ИИ будет думать и отвечать на соответствующем языке на протяжении всей сессии.

- **Полная цепочка инструментов**: выполнение bash, чтение/запись/редактирование файлов, поиск glob/grep, веб-поиск и загрузка, фоновые задачи, управление задачами и списками дел.

- **Система навыков (Skills)**: Загружайте знания предметной области по требованию (`SKILL.md`), чтобы ИИ был более профессиональным в конкретных сценариях.

- **Субагенты (Subagents)**: Делегируйте сложные задачи субагентам с независимым контекстом, чтобы не загрязнять основную сессию.

- **Хуки (Hooks)**: Хуки на Python или Shell, поддерживающие перехват до/после вызова инструментов, журналы аудита, автоматическое форматирование и контроль тестов.

- **Протокол MCP**: Подключение внешних серверов инструментов (GitHub, Filesystem и т. д.) через Model Context Protocol.

- **Сжатие контекста**: Двухуровневое сжатие (усечение результатов инструментов + резюме LLM) поддерживает очень длинные диалоги.

- **Безопасная песочница**: Белый список команд, обнаружение выхода за пределы пути, блокировка опасных команд, защита конфиденциальных файлов и перехват внедрения скриптов.

- **CLI в чёрно-золотой теме**: Адаптация ширины китайских символов, подсветка синтаксиса, раскраска diff и сворачивание размышлений.

# Установка

## Предварительные требования

- Python 3.10+ (требуется `tomllib`; встроен в 3.11+; на 3.10 установите `tomli`)
- pip

## Установка из исходников

### Два способа загрузки

1. `pip install https://github.com/Xu123-Bob/Baize.git`

    bash -- нажмите Win+R, введите `cmd`, затем выполните:

    baize

2. На странице репозитория нажмите `<> Code` --> `Download ZIP`.

(1) После распаковки перейдите в каталог:

    bash -- нажмите Win+R, введите cmd

    cd путь\к\распакованному\каталогу

    pip install -r requirements.txt

    python -m Baize

После установки нажмите Win+R, введите `cmd`, откройте CLI, введите `baize` и запустите.

(2) После загрузки ZIP установите локально. Распакуйте, перейдите в каталог и выполните:

    bash -- нажмите Win+R, введите cmd

    pip install .

После установки нажмите Win+R, введите `cmd`, откройте CLI, введите `baize` и запустите.

### Опционально: установка зависимостей доступа к данным (важно для анализа данных)

Если вы хотите, чтобы Baize управлял SPSS или базами данных SQL, установите дополнительные зависимости:

```bash
pip install -r requirements-data.txt
```

`requirements-data.txt` включает:
- `spss-studio-mcp`: MCP-сервер статистического анализа SPSS (требуется локально установленный IBM SPSS Statistics)
- `atengk-mcp-server-rdbms`: Универсальный MCP-сервер реляционных баз данных (PostgreSQL / MySQL / SQL Server / Oracle / Dameng и т. д.)
- `pyodbc`: Привязка Python ODBC, необходимая для SQL Server

Альтернативно, если проект установлен через `pyproject.toml`, можно использовать extras:

```bash
pip install -e ".[data]"          # Установить все зависимости доступа к данным
pip install -e ".[spss]"          # Только SPSS
pip install -e ".[sql]"           # Только универсальный SQL
pip install -e ".[sql-mssql]"     # Только SQL Server (включает pyodbc)
```

- **⚠️ Пользователи SQL Server: `pyodbc` — это только привязка Python. Вам также нужно установить Microsoft ODBC Driver 18 for SQL Server на уровне системы.**
- **⚠️ Пользователи SPSS: `spss-studio-mcp` — это только мостовой слой MCP. IBM SPSS Statistics (версии 20–31) должен быть установлен локально и иметь активную лицензию, а переменная окружения `SPSS_INSTALL_PATH` должна указывать на каталог установки SPSS. Полный статистический анализ с движком SPSS поддерживается в основном на Windows. На Linux/macOS возможен переход в «файловый режим» (чтение файлов `.sav`, просмотр метаданных, предварительный просмотр данных, но без статистического анализа).**

# Быстрый старт

## Запуск с API LLM

1. Первый запуск

```bash
baize
```

При первом запуске Baize автоматически создаёт два файла конфигурации:

```
~/.baize/config.toml   # Конфигурация бэкенда (выберите DeepSeek / OpenAI / Ollama)

~/.baize/.env          # Файл ключей
```

В Windows путь: `C:\Users\ВашеИмяПользователя\.baize\`.

**2. Выбор бэкенда**

Откройте `~/.baize/config.toml` и измените **active_provider** (этот шаг обязателен):

```toml
# Файл конфигурации Baize
# Измените active_provider для переключения бэкенда
# Возможные значения: "deepseek" / "qwen" / "kimi" / "glm" / "openai" / "ollama"

active_provider = "deepseek"

[model_providers.deepseek]
name = "DeepSeek"
base_url = "https://api.deepseek.com"
env_key = "DEEPSEEK_API_KEY"
model = "deepseek-flash"

[model_providers.qwen]
name = "Qwen"
base_url = "https://dashscope.aliyuncs.com/compatible-mode/v1"
env_key = "DASHSCOPE_API_KEY"
model = "qwen-plus"

[model_providers.kimi]
name = "Kimi"
base_url = "https://api.moonshot.cn/v1"
env_key = "MOONSHOT_API_KEY"
model = "kimi-k2.7-code"

[model_providers.glm]
name = "GLM"
base_url = "https://open.bigmodel.cn/api/paas/v4"
env_key = "ZHIPUAI_API_KEY"
model = "glm-4-plus"

[model_providers.openai]
name = "OpenAI"
base_url = "https://api.openai.com/v1"
env_key = "OPENAI_API_KEY"
model = "gpt-4o"

[model_providers.ollama]
name = "Ollama (локальный)"
base_url = "http://localhost:11434/v1"
env_key = ""
model = "qwen2.5:7b"
```

**3. Ввод API-ключа**

Отредактируйте `~/.baize/.env`. **Если вам нужно использовать конкретный LLM, удалите ведущий `#` в строке ключа этого провайдера, добавьте `#` перед ключами других LLM, чтобы заблокировать их вывод, введите API-ключ и обязательно сохраните файл. Он вступит в силу только после сохранения**:

```env
# ============================================================
# Файл ключей Baize
# ============================================================
# Заполняйте только ключ нужного вам бэкенда; остальные оставьте закомментированными.
# Имена переменных должны совпадать с полями env_key в config.toml.
#
# Расположение:
#   Linux / macOS: ~/.baize/.env
#   Windows:       C:\Users\ВашеИмяПользователя\.baize\.env
# ============================================================

# ---------- DeepSeek (бэкенд по умолчанию) ----------
# Получить: https://platform.deepseek.com/api_keys
DEEPSEEK_API_KEY=

# ---------- OpenAI или любой совместимый с OpenAI эндпоинт (опционально) ----------
# Подходит для Groq, Tongyi, Moonshot, Zhipu, OpenAI и т. д.
# Примечание: base_url настраивается в [model_providers.xxx] в config.toml, а не здесь.
# OPENAI_API_KEY=

# ---------- Tongyi Qianwen (опционально) ----------
# Получить: https://dashscope.console.aliyun.com/
# DASHSCOPE_API_KEY=

# ---------- Kimi / Moonshot (опционально) ----------
# Получить: https://platform.moonshot.cn/console/api-keys
# MOONSHOT_API_KEY=

# ---------- Zhipu GLM (опционально) ----------
# Получить: https://open.bigmodel.cn/usercenter/apikeys
# ZHIPUAI_API_KEY=

# ---------- Пользовательский шлюз (опционально) ----------
# CUSTOM_API_KEY=

# ---------- Ollama (локальная модель, ключ не требуется) ----------
# Просто убедитесь, что Ollama запущен на localhost:11434. Здесь настройка не нужна.
```

4. Перезапуск

```bash
baize
```

Если вы видите чёрно-золотой логотип и приветственное сообщение, запуск прошёл успешно.

## Локальные модели Ollama (нулевая стоимость)

Не хотите использовать облачный API? Используйте локальный Ollama:

    bash

    # 1. Установить Ollama: https://ollama.com/download
    # 2. Загрузить модель
    ollama pull qwen2.5:7b

    # 3. Запустить сервис Ollama
    ollama serve

    # 4. Изменить ~/.baize/config.toml
    active_provider = "ollama"

    # 5. Запустить Baize
    baize

Рекомендуемые модели: `qwen2.5:7b` (сильный китайский), `llama3.1:8b`, `deepseek-r1:7b`.

## Многоязычное взаимодействие

Baize поддерживает **девять языков**: китайский, английский, японский, корейский, испанский, французский, немецкий, русский и арабский.

Есть два способа переключения:

### Способ 1: просто говорите (автоматическое определение)

Baize автоматически определяет язык вашего ввода и переключается:

```
>>> 降旨：Hello, help me write a Python script
[Система] Обнаружен язык ввода: English. Baize переключился на взаимодействие на English.
(Baize отвечает на английском)

>>> 降旨：日本語で答えてください
[Система] Обнаружен язык ввода: 日本語. Baize переключился на взаимодействие на 日本語.
(Baize отвечает на японском)
```

### Способ 2: ручная команда

```
>>> 降旨：/lang                # Показать текущий язык и доступный список
[Система] Текущий язык: 中文 (zh)
[Система] Доступные языки:
    zh    中文 ←
    en    English
    ja    日本語
    ko    한국어
    es    Español
    fr    Français

>>> 降旨：/lang English        # Переключить по названию языка
>>> 降旨：/lang ja             # Переключить по коду языка
>>> 降旨：/lang 西班牙语        # Название на китайском тоже работает
```

Поддерживается **название языка / код языка / название на китайском / родное название**. Например, для переключения на английский подойдёт любое из `English`, `en`, `英语` или `英文`.

## Встроенные команды

- `/exit`, `/quit` --> Выйти из Baize
- `/clear` --> Очистить историю диалога, списки дел, записи размышлений и записи инструментов
- `/compact` --> Вручную сжать контекст (используйте, когда диалог слишком длинный)
- `/commit` --> Сохранить текущую сессию и закоммитить в Git (если внутри Git-репозитория)
- `/lang` --> Показать текущий язык; `/lang en` переключает на английский (поддерживает коды или названия языков)
- `/skills` --> Список всех доступных навыков
- `/skills reload` --> Перезагрузить каталог пользовательских навыков
- `/unload` --> Выгрузить текущий активный навык
- `/show thought` --> Показать полную запись размышлений
- `/show tool` --> Показать записи вызовов инструментов
- `/show all` --> Показать всю историю сессии
- `/имя-навыка` --> Загрузить указанный навык (поддерживает нечёткое сопоставление)
- `/privacy` --> Управление маскированием конфиденциальности (`on / off / strict / status / rules / test / clear`)
- `/privacy rule-off <name>` --> Отключить правило маскирования (например, `/privacy rule-off phone_intl`)
- `/privacy rule-on <name>` --> Снова включить правило

# Механизмы расширения

Baize поддерживает четыре механизма расширения. Разместите их в текущем рабочем каталоге, и они вступят в силу.

## Навыки (Skills)

Пишите знания предметной области в `./skills/<имя-навыка>/SKILL.md`. ИИ будет проактивно загружать их при встрече со сложными задачами.

    markdown

    ---
    name: pandas-eda

    description: Лучшие практики исследовательского анализа данных с pandas

    tags: data,python
    ---

    # Руководство по Pandas EDA

    ## Основные шаги
    1. df.info() для проверки типов полей и пропущенных значений
    2. df.describe() для статистического описания
    ...

## Хуки (Hooks)

Разместите `PreToolUse-*.sh`, `PostToolUse-*.sh` и `Stop-*.sh` в `./hooks/`. Они получают JSON-ввод и возвращают решение:

```bash
#!/bin/bash
# PreToolUse-guard.sh
read -r input

  echo '{"hookSpecificOutput":{"permissionDecision":"block","permissionDecisionReason":"Deletion prohibited"}}'

```

Хуки на Python могут напрямую вызывать встроенные API (см. функции `hook_*` в `Baize.py`).

# Безопасность (ядро)

Baize по умолчанию включает следующие механизмы безопасности:

- **Белый список команд**: Разрешены только общие команды, такие как `ls`, `cat`, `grep`, `git` и `python3`.
- **Обнаружение выхода за пределы пути**: Все файловые операции ограничены текущим рабочим каталогом и `/tmp`.
- **Блокировка опасных команд**: Блокирует такие шаблоны, как `rm -rf /`, fork bomb, `curl | sh` и `git push --force`.
- **Защита конфиденциальных файлов**: Запрещает изменение `.env`, `.ssh/`, `id_rsa`, `*.pem` и т. д.
- **Перехват внедрения скриптов**: Обнаруживает обходы вроде `python -c "os.system(...)"`.
- **Ограничения ресурсов процессов**: Ограничивает CPU, память и количество процессов на Linux/macOS.
- **Маскирование конфиденциальности (двунаправленное обратимое)**: PII заменяются случайными заполнителями на выходе и восстанавливаются на входе; записи на диск маскируются независимо.
- **Устойчивость к инъекции заполнителей**: 64-битные криптографические случайные токены + нейтрализация на стороне ввода + изоляция сессий.
- **Маскирование журналов аудита**: `hook_audit_log` маскирует перед записью, усекает и отказывается записывать при сбое.

Если вам нужно ослабить ограничения в доверенных проектах, вы можете изменить `ALLOWED_COMMANDS` и `FORBIDDEN_PATH_PATTERNS` в `Baize.py`.

# Маскирование конфиденциальности (ядро)

Baize включает встроенный механизм защиты конфиденциальности **двунаправленный обратимый + маскирование на диске**, покрывающий весь путь от ввода до диска:

- **На выходе**: Перед отправкой в LLM PII заменяются непредсказуемыми заполнителями.
- **На входе**: Заполнители в ответах LLM восстанавливаются в исходный текст.
- **Запись на диск**: Файлы сессий, сжатые транскрипты и журналы аудита **независимо маскируются** перед записью на диск. Открытый текст не остаётся на диске.

**Отключено по умолчанию**; включайте при необходимости.

## Два способа включения

### Способ 1: естественный язык

Скажите прямо в диалоге:

```
>>> 降旨：Включить маскирование конфиденциальности
[Система] Маскирование конфиденциальности включено (стандартный режим).

>>> 降旨：Включить строгое маскирование
[Система] Маскирование конфиденциальности включено (строгий режим).

>>> 降旨：Отключить защиту конфиденциальности
[Система] Маскирование конфиденциальности отключено.
```

### Способ 2: слэш-команды

- `/privacy on` включает стандартный режим
- `/privacy strict` включает строгий режим
- `/privacy off` отключает
- `/privacy status` показывает состояние, ID сессии, количество правил и статистику LRU/TTL
- `/privacy rules` перечисляет все правила (включая состояние)
- `/privacy rule-off <name>` отключает правило
- `/privacy rule-on <name>` снова включает его
- `/privacy test <текст>` тестирует результат маскирования
- `/privacy clear` очищает отображение заполнителей и **меняет ID сессии**

## Два режима

**Стандартный**: Номера мобильных телефонов материкового Китая, номера удостоверений личности, номера банковских карт (проверка Луна), электронные почты, IPv4/IPv6, API-ключи OpenAI/Anthropic/GitHub/AWS, Bearer-токены, блоки приватных ключей, поля паролей, учётные данные URL.

**Строгий**: Все стандартные правила + китайские имена, номера QQ, идентификаторы WeChat, номера автомобильных номеров материкового Китая.

## Как это работает

Пользовательский ввод (с реальными PII) → сообщения хранят исходный текст

↓ `sanitize_messages()`

В LLM отправляется `[[PHONE_1]]`, `[[EMAIL_1]]`

↓ Ответ LLM

Возвращённые заполнители → `restore_message()`

Восстанавливаются в исходный текст → запись на диск / отображение / выполнение инструментов

- **Маскирование конфиденциальности (двунаправленное обратимое)**: PII заменяются случайными заполнителями на выходе и восстанавливаются на входе; записи на диск маскируются независимо.
- **Устойчивость к инъекции заполнителей**: 64-битные криптографические случайные токены + нейтрализация на стороне ввода + изоляция сессий.
- **Маскирование журналов аудита**: `hook_audit_log` маскирует перед записью, усекает и отказывается записывать при сбое.

## Интеллектуальная классификация параметров инструментов

**Маскируются** (текстовые параметры, не участвующие в реальном выполнении):

- `todo`, `ask_user_question`, `task_create`, `task_update`

**Не маскируются** (пути/команды/URL реально используются):

- `run_read` / `run_write` / `run_edit` / `run_glob` / `run_grep` (пути используются для ввода-вывода)
- `run_bash` / `background_run` (команды выполняются)
- `run_webfetch` / `web_search` (URL реально отправляются в сеть)
- `set_workspace` (путь используется для `chdir`)
- `load_skills` (имена навыков перечисляются)
- `agent` (контекст субагента маскируется независимо)
- `mcp_*` (неизвестная семантика; обрабатывается консервативно)

**Всё маскируется при записи на диск** (поскольку содержимое диска не перевыполняется, приоритет — безопасность).

## Маскирование на диске

**Включено по умолчанию**, независимо от маскирования в памяти. Даже при `/privacy off` (без маскирования в памяти) записи на диск проходят как минимум через стандартные правила.

**Ключевые особенности**:

- Маскирование на диске использует **независимую одноразовую таблицу отображения**. Заполнители, записанные на диск, **не могут быть восстановлены**, поскольку таблица отображения уничтожается.
- Если маскирование на диске **не удаётся, Baize отказывается записывать открытый текст** (без деградации, без молчаливого пропуска).
- Если старый файл сессии содержит открытый текст, он будет автоматически маскирован и перезаписан при первом сохранении.

**Как отключить** (не рекомендуется): Установите `PERSIST_REDACT_ENABLED = False` в `Baize.py`.

# Доступ к данным (ядро)

Baize подключается к корпоративному программному обеспечению для анализа данных через **MCP (Model Context Protocol)**. Основная программа не требует изменений — достаточно зарегистрировать сервер в `MCP/mcp_config.json`.

## Интеграция SPSS

### Предварительные требования

- IBM SPSS Statistics установлен локально (версии 20–31; рекомендуется Windows)
- SPSS лицензирован и может нормально запускаться

### Шаги настройки

1. **Найдите каталог установки SPSS**: Путь по умолчанию обычно `C:\Program Files\IBM\SPSS Statistics\`, за которым следует номер версии (например, `31`).

2. **Установите переменную окружения** (в `.env` или системных переменных окружения):

```text
SPSS_INSTALL_PATH=C:\Program Files\IBM\SPSS Statistics\31
```

3. **Проверьте состояние**:

```bash
spss-studio-mcp status
```

Ожидаемый вывод:

```text
=== SPSS MCP Capability Status ===
pyreadstat : OK v1.3.6
pandas     : OK v3.0.2
SPSS batch : OK
```

4. **Зарегистрируйте в `MCP/mcp_config.json`**:

```json
{
  "mcpServers": [
    {
      "name": "spss",
      "command": "spss-studio-mcp",
      "args": ["serve", "--transport", "stdio"],
      "env": {
        "SPSS_INSTALL_PATH": "C:\\Program Files\\IBM\\SPSS Statistics\\31"
      },
      "enabled": true
    }
  ]
}
```

### Если появилось `SPSS batch: NOT FOUND`

Это означает, что `spss-studio-mcp` не нашёл движок SPSS, но `pyreadstat` + `pandas` работают. В этом случае он переходит в **файловый режим**:

- Может читать `.sav`, просматривать метаданные, предварительно просматривать данные и конвертировать CSV ↔ SAV
- Не может выполнять статистику (t-тест, регрессия, ANOVA и т. д.)

Решение: Правильно настройте `SPSS_INSTALL_PATH` в `MCP/mcp_config.json` или примите деградацию до файлового режима.

## Интеграция SQL

### Поддерживаемые базы данных

PostgreSQL, MySQL, MariaDB, SQL Server, Oracle, Dameng, Kingbase, TiDB, OceanBase и т. д. (на основе драйверов SQLAlchemy 2.0).

### Шаги настройки

1. **Подготовьте учётную запись базы данных только для чтения** (настоятельно рекомендуется):

```sql
CREATE USER baize_ro WITH PASSWORD 'xxx';
GRANT SELECT ON ALL TABLES IN SCHEMA public TO baize_ro;
```

2. **Подготовьте строку подключения**:

- PostgreSQL --> `postgresql+psycopg://user:pwd@host:5432/db`
- MySQL --> `mysql+pymysql://user:pwd@host:3306/db`
- SQL Server --> `mssql+pyodbc://user:pwd@host:1433/db?driver=ODBC+Driver+18+for+SQL+Server`
- Oracle --> `oracle+oracledb://user:pwd@host:1521/?service_name=ORCL`

3. **Зарегистрируйте в `MCP/mcp_config.json`**:

```json
{
  "mcpServers": [
    {
      "name": "sql",
      "command": "atengk-mcp-server-rdbms",
      "args": ["--transport", "stdio"],
      "env": {
        "DATABASE_URL": "postgresql+psycopg://baize_ro:pwd@localhost:5432/prod"
      },
      "enabled": true
    }
  ]
}
```

### Встроенные средства защиты

`atengk-mcp-server-rdbms` обеспечивает несколько уровней защиты:

- **Защита SELECT на уровне AST**: Использует `sqlglot` для разбора синтаксического дерева и физически блокирует операции записи, такие как `DELETE/UPDATE/DROP/TRUNCATE`.
- **Автоматическое добавление LIMIT**: Запросы без указанного количества строк принудительно дополняются `LIMIT 100`, чтобы предотвратить исчерпание памяти при полной выборке таблицы.
- **Только чтение по умолчанию**: Операции записи должны быть явно разрешены через `--allow-dml` / `--allow-ddl`.
- **Перехват SQL-инъекций**: На уровне AST отклоняет вредоносные инструкции, построенные конкатенацией строк.

### Настройка нескольких баз данных одновременно

Если вы хотите подключиться к нескольким базам данных одновременно, зарегистрируйте несколько серверов:

```json
{
  "mcpServers": [
    {
      "name": "sql_prod",
      "command": "atengk-mcp-server-rdbms",
      "args": ["--transport", "stdio"],
      "env": { "DATABASE_URL": "postgresql+psycopg://ro:pwd@prod:5432/db" },
      "enabled": true
    },
    {
      "name": "sql_warehouse",
      "command": "atengk-mcp-server-rdbms",
      "args": ["--transport", "stdio"],
      "env": { "DATABASE_URL": "mysql+pymysql://ro:pwd@dw:3306/analytics" },
      "enabled": true
    }
  ]
}
```

Baize автоматически объединит все их инструменты в `MATERTOOLS`, и LLM выберет подходящий в зависимости от задачи.

# Разработка

## Запуск тестов

Проект использует pytest. Перед разработкой установите пакет в редактируемом режиме с зависимостями для разработки:
```
    pip install -e ".[dev]"
```
Запустить все тесты:
```
    python -m pytest tests/ -v
```
Запустить один файл:
```
    python -m pytest tests/test_history.py -v
```
## Соглашения о структуре кода

- `agent/`: Основной пакет, поставляемый с пакетом. Вся логика выполнения и ресурсы (skills, subagent, hooks, MCP) находятся здесь.
- `agent/core/`: Модули чистой логики без внешних побочных эффектов. **Они должны тестироваться независимо.** Добавляйте новую логику такого рода здесь и включайте тесты.
- `tests/`: Соответствует один к одному исходным файлам в `agent/`, именуется `test_<модуль>.py`.
- Любая функция с внешними зависимостями (сеть, диск, глобальное состояние) должна внедрять зависимости через параметры, чтобы их можно было заменить в тестах.

О: Нет. Просто измените `active_provider` в `~/.baize/config.toml`.

- В: Нужен ли API-ключ для локального Ollama?

О: Нет. Установите `active_provider = "ollama"` и оставьте `env_key` пустым.

- В: Как переключить рабочий каталог?

О: В диалоге просто скажите «переключись на /path/to/project», и Baize вызовет инструмент `set_workspace`.

- В: Что произойдёт, если контекст станет слишком длинным?

О: Baize автоматически выполняет двухуровневое сжатие: сначала усекает старые результаты инструментов, затем запрашивает резюме у LLM. Вы также можете вручную использовать `/compact`.

- В: Удалит ли он мои файлы случайно?

О: Белый список команд по умолчанию блокирует опасные операции, такие как `rm -rf /`; перед записью файлов он показывает diff и запрашивает подтверждение.

- В: Как подключить Baize к SPSS?

О: 1. Установите `pip install -r requirements-data.txt`; 2. Установите переменную окружения `SPSS_INSTALL_PATH`, указывающую на каталог установки SPSS; 3. Включите сервер `spss` в `MCP/mcp_config.json`. Подробнее см. раздел «Доступ к данным (SPSS / SQL)».

- В: Что делать с `SPSS batch: NOT FOUND`?

О: Это означает, что движок SPSS не найден. Проверьте, правильно ли `SPSS_INSTALL_PATH` указывает на каталог, содержащий `stats.exe`; если вы обрабатываете только файлы `.sav`, можете игнорировать это предупреждение (будет переход в файловый режим).

- В: Что ещё нужно установить для подключения к базе данных SQL?

О: Установите `atengk-mcp-server-rdbms` на уровне Python (это делает `pip install`). **Пользователям SQL Server также нужно установить Microsoft ODBC Driver 18 на уровне системы**, что нельзя сделать через pip.

- В: Удалит ли Baize случайно данные моей базы данных?

О: Нет. SQL MCP по умолчанию разрешает только SELECT и блокирует все операции записи на уровне синтаксического дерева AST. Тем не менее настоятельно рекомендуется создать **учётную запись базы данных только для чтения** для Baize в качестве второй меры защиты.

- В: Утекут ли данные из результатов анализа SPSS в LLM?

О: Если включено маскирование конфиденциальности (`/privacy on`), результаты инструментов автоматически маскируются для номеров телефонов, электронных почт, удостоверений личности и других PII перед отправкой в LLM. **Однако рекомендуется также использовать учётную запись базы данных только для чтения + выборку данных** (запрашивать только необходимые поля), чтобы снизить риск.

- В: Почему после добавления SPSS/SQL Baize становится медленнее и использует больше токенов в каждом диалоге?

О: Потому что определения инструментов, предоставляемые серверами MCP, отправляются в LLM на каждом ходу диалога. В SPSS более 60 инструментов, что добавляет фиксированные накладные расходы около 6 000–12 000 токенов. Если ваш обычный рабочий процесс не связан со SPSS, вы можете установить его `enabled` в `false` и включать при необходимости.
