Китайский божественный дух воплощается в VibeCoding — безопасный помощник для анализа данных.

**Открытый Coding Agent CLI с мощной защитой приватности и многоязычным взаимодействием. Поддерживает несколько бэкендов (DeepSeek / OpenAI-совместимые / GLM / Qwen / Kimi / локальный Ollama), а также вызов инструментов, загрузку навыков, делегирование подагентам, сжатие контекста и безопасную песочницу.**

----------

# Ключевые преимущества

## Защита приватности

- **Двунаправленная обратимая защита приватности**: перед отправкой в LLM ваша конфиденциальная информация заменяется плейсхолдерами, а после получения ответа автоматически восстанавливается. Весь процесс незаметен для вас — история, аргументы инструментов и финальный ответ, которые вы видите, всегда содержат исходный текст, а LLM видит только плейсхолдеры вроде `[[PHONE_1]]` и `[[EMAIL_1]]`.
- **Несколько способов включения защиты приватности**: можно включить естественным языком в диалоге или использовать более точную команду `/privacy`.
- **Локализация агента**: продукт не имеет удалённой базы данных и работает полностью локально. Он не собирает информацию о пользователе.

## Многоязычное взаимодействие

- **Поддержка девяти языков**: 中文, English, 日本語, 한국어, Español, Français, deutsch, русский, العربية.
- **Несколько способов переключения языка**: можно прямо сказать язык, например `please speak with english`, чтобы переключиться на английский, или использовать `/lang ja` для переключения на японский.

# Возможности

- **Поддержка нескольких бэкендов**: DeepSeek, любой OpenAI-совместимый API (GLM / Qwen / Kimi / OpenAI) и локальный Ollama. Переключение одной строкой.

- **Запуск без настройки**: при первом запуске конфигурационные файлы создаются автоматически. Ключ нужно ввести только один раз.

- **Маскирование персональных данных**: перед отправкой в LLM автоматически распознаются и заменяются на плейсхолдеры телефоны, email, номера удостоверений, банковские карты, API-ключи и другие PII; в ответе они восстанавливаются. Два уровня (стандартный / строгий), переключаются естественным языком или командой `/privacy`.

- **Многоязычное взаимодействие**: свободное переключение между китайским / английским / японским / корейским / испанским / французским / немецким / русским / арабским — достаточно сказать `English` или выполнить `/lang ja`, и ИИ будет думать и отвечать на этом языке.

- **Полный инструментарий**: выполнение bash-команд, чтение/запись/редактирование файлов, поиск glob/grep, веб-поиск и извлечение страниц, фоновые задачи, управление задачами и todo.

- **Система навыков (Skills)**: доменные знания (SKILL.md) загружаются по требованию — ИИ становится профессиональнее в конкретных сценариях.

- **Подагенты (Subagents)**: сложные задачи делегируются подагентам с независимым контекстом, что не загрязняет основную сессию.

- **Хуки (Hooks)**: хуки на Python или Shell для перехвата до/после вызова инструмента, ведения аудита, автоформатирования и «тестовых ворот».

- **Протокол MCP**: подключение внешних серверов инструментов (GitHub, Filesystem и др.) через Model Context Protocol.

- **Сжатие контекста**: двухуровневое сжатие (усечение старых результатов инструментов + суммаризация через LLM) для очень длинных диалогов.

- **Безопасная песочница**: белый список команд, детекция выхода за пределы рабочей директории, блокировка опасных команд, защита конфиденциальных файлов, перехват инъекций скриптов.

- **CLI в чёрно-золотой теме**: адаптивная ширина для китайского, подсветка кода, раскраска Diff, сворачивание размышлений.

# Установка

## Требования

- Python 3.10+ (нужен `tomllib`; встроен начиная с 3.11; на 3.10 установите `tomli`)
- pip

## Установка из исходников

### Два способа загрузки

1. `pip install https://github.com/Xu123-Bob/Baize.git`

bash -- Нажмите Win+R, введите cmd и выполните:

```bash
baize
```

2. На странице репозитория нажмите `<> Code` → `Download ZIP`

(1) После распаковки перейдите в каталог:

bash -- Нажмите Win+R, введите cmd

```bash
cd путь/к/распакованному/каталогу
pip install -r requirements.txt
python -m Baize
```

После установки нажмите Win+R, введите cmd, откройте CLI и введите `baize`.

(2) Локальная установка из ZIP-архива:

bash -- Нажмите Win+R, введите cmd

```bash
pip install .
```

После установки нажмите Win+R, введите cmd, откройте CLI и введите `baize`.

### Опционально: установка зависимостей доступа к данным

Если нужно, чтобы Baize управлял SPSS или базами SQL, установите дополнительно:

```bash
pip install -r requirements-data.txt
```

`requirements-data.txt` включает:

- `spss-studio-mcp`: MCP server статистического анализа SPSS (требуется локально установленный IBM SPSS Statistics)
- `atengk-mcp-server-rdbms`: MCP server универсальных реляционных баз данных (PostgreSQL / MySQL / SQL Server / Oracle / DM и др.)
- `pyodbc`: Python-привязка ODBC, необходимая для SQL Server

Или, если проект установлен через `pyproject.toml`, используйте extras:

```bash
pip install -e ".[data]"          # Установить все зависимости доступа к данным
pip install -e ".[spss]"          # Только SPSS
pip install -e ".[sql]"           # Только универсальный SQL
pip install -e ".[sql-mssql]"     # Только SQL Server, включая pyodbc
```

- **⚠️ Пользователям SQL Server: `pyodbc` — это только Python-привязка. На уровне системы также требуется Microsoft ODBC Driver 18 for SQL Server.**
- **⚠️ Пользователям SPSS: `spss-studio-mcp` — это только мост MCP. IBM SPSS Statistics (версия 20–31) должен быть установлен и лицензирован локально, а переменная окружения `SPSS_INSTALL_PATH` должна указывать на каталог установки SPSS. Полный статистический анализ в основном поддерживается в Windows. В Linux/macOS возможен переход в «файловый режим» (чтение `.sav`, просмотр метаданных, предпросмотр данных, но без статистического анализа).**

# Быстрый старт

1. Первый запуск

```bash
baize
```

При первом запуске Baize автоматически создаёт два файла:

```text
~/.baize/config.toml   # конфигурация бэкендов (DeepSeek / OpenAI / Ollama)
~/.baize/.env          # файл с ключами
```

Путь в Windows: `C:\Users\ваше-имя\.baize\`.

2. Выбор бэкенда

Откройте `~/.baize/config.toml` и измените `active_provider`:

```toml
# Файл конфигурации Baize
# Измените значение active_provider для переключения бэкенда
# Дополнительные значения: "deepseek" / "qwen" / "kimi" / "glm" / "openai" / "ollama"

active_provider = "deepseek"

[model_providers.deepseek]
name = "DeepSeek"
base_url = "https://api.deepseek.com"
env_key = "DEEPSEEK_API_KEY"
model = "deepseek-flash"

[model_providers.qwen]
name = "Qwen"
base_url = "https://dashscope.aliyuncs.com/compatible-mode/v1"
env_key = "DASHSCOPE_API_KEY"
model = "qwen-plus"

[model_providers.kimi]
name = "Kimi"
base_url = "https://api.moonshot.cn/v1"
env_key = "MOONSHOT_API_KEY"
model = "kimi-k2.7-code"

[model_providers.glm]
name = "GLM"
base_url = "https://open.bigmodel.cn/api/paas/v4"
env_key = "ZHIPUAI_API_KEY"
model = "glm-4-plus"

[model_providers.openai]
name = "OpenAI"
base_url = "https://api.openai.com/v1"
env_key = "OPENAI_API_KEY"
model = "gpt-4o"

[model_providers.ollama]
name = "Ollama (местный)"
base_url = "http://localhost:11434/v1"
env_key = ""
model = "qwen2.5:7b"
```

3. Ввод ключа

Отредактируйте `~/.baize/.env`, **если нужно использовать определённый LLM, удалите предыдущий `#` и добавьте `#` перед другим LLM, чтобы блокировать вывод API других LLM. После ввода API-ключа обязательно сохраняйте его — только после сохранения он станет действительным**:

```env
# ============================================================
# Файл с ключом Baize
# ============================================================
# Заполните только ключ для используемого бэкенда, остальное оставьте как комментарии.
# Название переменной должно совпадать с полем env_key в файле config.toml.
#
# Положение:
#   Linux / macOS: ~/.baize/.env
#   Windows:       C:\Users\ваше имя пользователя\.baize\.env
# ============================================================

# ---------- DeepSeek(бэкенд по умолчанию) ----------
# Получить адрес：https://platform.deepseek.com/api_keys
DEEPSEEK_API_KEY=

# ---------- OpenAI или любой интерфейс, совместимый с OpenAI (по желанию) ----------
# Поддерживается для Groq, Tongyi, Moonshot, Zhipu, OpenAI и других
# Обратите внимание: base_url настраивается в [model_providers.xxx] в config.toml, здесь не указывается
# OPENAI_API_KEY=

# ---------- Qwen（Опционально） ----------
# Получить адрес：https://dashscope.console.aliyun.com/
# DASHSCOPE_API_KEY=

# ---------- Kimi / Moonshot（Опционально） ----------
# Получить адрес：https://platform.moonshot.cn/console/api-keys
# MOONSHOT_API_KEY=

# ----------  GLM（Опционально） ----------
# Получить адрес：https://open.bigmodel.cn/usercenter/apikeys
# ZHIPUAI_API_KEY=

# ---------- Кастомный шлюз (по желанию) ----------
# CUSTOM_API_KEY=

# ---------- Ollama (локальная модель, без ключа) ----------
# Достаточно просто убедиться, что Ollama работает на localhost:11434, конфигурации здесь не требуется
```

4. Перезапуск

```bash
baize
```

Если вы видите чёрно-золотой логотип и приветствие — запуск прошёл успешно.

# Примеры использования

После запуска опишите задачу естественным языком в приглашении `>>> 降旨：`:

```text
>>> 降旨：Напиши скрипт на Python для скрапинга Douban Top250 и сохрани в CSV

>>> 降旨：Проверь ошибки типов во всех Python-файлах в src/

>>> 降旨：Найди в этом репозитории все места, где используется requests, и замени на httpx
```

## Многоязычное взаимодействие

Baize поддерживает **девять языков**: 中文, English, 日本語, 한국어, Español, Français, deutsch, русский, العربية.

Переключение двумя способами:

### Способ 1: просто говорите (автоопределение)

Baize автоматически определяет язык ввода и переключается:

```text
>>> 降旨：Привет, помоги написать скрипт на Python
[system] Обнаружен язык ввода: Русский. Baize переключился на Русский.
(отвечает по-русски)

>>> 降旨：Hello, write me a script
[system] Обнаружен язык ввода: English. Baize переключился на English.
(отвечает по-английски)
```

### Способ 2: команда вручную

```text
>>> 降旨：/lang                # Показать текущий язык и список доступных
[system] Текущий язык: 中文 (zh)
[system] Доступные языки:
    zh    中文 ←
    en    English
    ja    日本語
    ko    한국어
    es    Español
    fr    Français
    de    Deutsch
    ru    Русский
    ar    العربية

>>> 降旨：/lang English        # Переключить по названию языка
>>> 降旨：/lang ja             # Переключить по коду языка
>>> 降旨：/lang 西班牙语        # Название по-китайски тоже работает
```

Поддерживается **название языка / код языка / китайское название / локализованное название**. Например, чтобы переключиться на английский, можно ввести `English`, `en`, `英语` или `英文`.

## Встроенные команды

- `/exit`, `/quit` --> Выйти из Baize
- `/clear` --> Очистить историю диалога, todo, записи размышлений и инструментов
- `/compact` --> Вручную сжать контекст (когда диалог слишком длинный)
- `/commit` --> Сохранить текущую сессию и закоммитить в Git (если внутри Git-репозитория)
- `/lang` --> Показать текущий язык; `/lang en` переключает на английский (принимает код или название)
- `/skills` --> Список всех доступных навыков
- `/skills reload` --> Перезагрузить пользовательский каталог навыков
- `/unload` --> Выгрузить активный навык
- `/show thought` --> Показать полные записи размышлений
- `/show tool` --> Показать записи вызовов инструментов
- `/show all` --> Показать всю историю сессии
- `/имя-навыка` --> Загрузить указанный навык (с нечётким сопоставлением)
- `/privacy` --> Управление маскированием персональных данных (см. раздел «Маскирование персональных данных»)

## Примеры использования доступа к данным

После настройки SPSS / SQL можно управлять ими на естественном языке:

```text
>>> 降旨：Открой data.sav в SPSS и скажи список переменных и размер выборки

>>> 降旨：Сделай описательную статистику по data.sav, затем запусти линейную регрессию

>>> 降旨：Найди в таблице sales заказы за прошлый месяц с суммой больше 100 000, сгруппированные по клиентам

>>> 降旨：Экспортируй результат анализа SPSS в CSV, затем свяжи его с мастер-данными клиентов через SQL
```

# Локальные модели Ollama (бесплатно)

Не хотите облачный API? Используйте локальный Ollama:

```bash
# 1. Установите Ollama: https://ollama.com/download
# 2. Загрузите модель
ollama pull qwen2.5:7b

# 3. Запустите сервис Ollama
ollama serve

# 4. Измените ~/.baize/config.toml
active_provider = "ollama"

# 5. Запустите Baize
baize
```

Рекомендуемые модели: `qwen2.5:7b` (сильный китайский), `llama3.1:8b`, `deepseek-r1:7b`.

# Механизмы расширения

Baize поддерживает четыре способа расширения. Достаточно разместить их в текущей рабочей директории.

## Навыки (Skills)

Пишите доменные знания в `./skills/имя-навыка/SKILL.md`. ИИ будет сам загружать их при сложных задачах.

```markdown
---
name: pandas-eda
description: Лучшие практики разведочного анализа данных с pandas
tags: data,python
---

# Руководство по Pandas EDA

## Основные шаги
1. df.info() — типы полей и пропуски
2. df.describe() — описательная статистика
...
```

Также можно загрузить вручную командой `/pandas-eda`.

## Подагенты (Subagents)

Определите специализированных подагентов в `./subagent/роль/AGENT.md`. Главный агент может делегировать задачи через инструмент `agent`.

```markdown
---
name: code-reviewer
description: Строгий ревьюер кода
---

Вы — старший ревьюер кода. При ревью в первую очередь обращайте внимание на:
1. Граничные условия и обработку ошибок
2. Утечки ресурсов
3. Потокобезопасность
...
```

## Хуки (Hooks)

Разместите в `./hooks/`:

- `PreToolUse-*.sh`
- `PostToolUse-*.sh`
- `Stop-*.sh`

Они получают JSON на вход и возвращают решение:

```bash
#!/bin/bash

# PreToolUse-guard.sh

read -r input

if echo "$input" | grep -q "rm -rf"; then
  echo '{"hookSpecificOutput":{"permissionDecision":"block","permissionDecisionReason":"Удаление запрещено"}}'
fi
```

Python-хуки могут напрямую вызывать встроенный API (см. функции `hook_*` в `Baize.py`).

## Серверы MCP

Настройте внешние серверы инструментов в `./MCP/mcp_config.json`:

```json
{
```

# Безопасность

По умолчанию Baize включает следующие механизмы:

- **Белый список команд**: разрешены только распространённые команды — `ls`, `cat`, `grep`, `git`, `python3` и т. п.
- **Детекция выхода за пределы**: все файловые операции ограничены текущей рабочей директорией и `/tmp`.
- **Блокировка опасных команд**: блокируются `rm -rf /`, fork-бомбы, `curl | sh`, `git push --force` и другие шаблоны.
- **Защита конфиденциальных файлов**: запрещено изменять `.env`, `.ssh/`, `id_rsa`, `*.pem` и т. п.
- **Перехват инъекций скриптов**: обнаружение обходов вида `python -c "os.system(...)"`.
- **Ограничение ресурсов процесса**: в Linux/macOS ограничиваются CPU, память и число процессов.

Если в доверенном проекте нужно ослабить ограничения, измените `ALLOWED_COMMANDS` и `FORBIDDEN_PATH_PATTERNS` в `Baize.py`.

# Маскирование персональных данных

Baize включает **двунаправленный обратимый** механизм маскирования персональных данных. Конфиденциальная информация заменяется плейсхолдерами перед отправкой в LLM и автоматически восстанавливается в ответе — полностью прозрачно для пользователя. Всё, что видите вы (история, аргументы инструментов, финальный ответ), всегда содержит исходный текст; всё, что видит LLM, — это `[[PHONE_1]]`, `[[EMAIL_1]]` и т. п.

**По умолчанию выключено.** Включается при необходимости.

## Два способа включения

### Способ 1: естественный язык

```text
>>> 降旨：включи маскирование персональных данных
[system] Маскирование персональных данных включено (стандартный режим).

>>> 降旨：включи строгое маскирование
[system] Маскирование персональных данных включено (строгий режим).

>>> 降旨：выключи защиту персональных данных
[system] Маскирование персональных данных выключено.
```

### Способ 2: слэш-команды

- `/privacy on` Включить стандартный режим
- `/privacy strict` Включить строгий режим (дополнительно: имена, номера машин, QQ, WeChat)
- `/privacy off` Выключить
- `/privacy status` Показать текущее состояние и статистику
- `/privacy rules` Вывести все правила
- `/privacy test` <текст> Протестировать маскирование
- `/privacy clear` Очистить карту плейсхолдеров

## Два уровня

**Стандартный**: мобильные номера материкового Китая, удостоверения личности, банковские карты (проверка Луна), email, IPv4/IPv6, ключи API OpenAI/Anthropic/GitHub/AWS, Bearer-токены, блоки приватных ключей, поля паролей, учётные данные в URL

**Строгий**: всё из стандартного + китайские имена, номера QQ, идентификаторы WeChat, автомобильные номера материкового Китая

## Как это работает

Ввод пользователя (с реальными PII) → сообщения хранят исходный текст

↓ sanitize_messages()

Что видит LLM: [[PHONE_1]], [[EMAIL_1]]

↓ ответ LLM

Плейсхолдеры → restore_message()

Восстановлено в оригинал → сохранение / отображение / выполнение

**Один и тот же исходный текст переиспользует один и тот же плейсхолдер**, поэтому один номер телефона остаётся `[[PHONE_1]]` на протяжении всей сессии.

**Аргументы инструментов различаются по чувствительности**: у чисто текстовых инструментов (`todo`, `ask_user_question`, `task_*`) аргументы маскируются; у инструментов, работающих с путями/командами/URL (`run_read`, `run_bash`, `run_webfetch`), они не трогаются — иначе выполнение провалится из-за подменённого пути.

**Подагенты также защищены**: задачи, делегированные главным агентом, проходят тот же конвейер маскирования и восстановления.

## Пример

```text
>>> 降旨：/privacy test Мой телефон 13812345678, email a@b.com
Исходный: Мой телефон 13812345678, email a@b.com
Маска   : Мой телефон [[PHONE_1]], email [[EMAIL_1]]
Восстан.: Мой телефон 13812345678, email a@b.com

>>> 降旨：/privacy status
[Маскирование персональных данных]
Текущий режим  : стандартный
Активных правил: 15 / 19
Плейсхолдеров  : 2
Вызовов маскирования: 3
Вызовов восстановления: 3
```

# Доступ к данным

Baize подключается к корпоративному программному обеспечению для анализа данных через **MCP (Model Context Protocol)**. Основная программа не требует изменений — достаточно зарегистрировать server в `MCP/mcp_config.json`.

## Интеграция SPSS

### Предварительные условия

- IBM SPSS Statistics установлен локально (версия 20–31, рекомендуется Windows)
- SPSS лицензирован и正常но запускается

### Шаги настройки

1. **Найдите каталог установки SPSS:** путь по умолчанию обычно `C:\Program Files\IBM\SPSS Statistics\` с номером версии, например `31`.

2. **Задайте переменную окружения** в `.env` или системных переменных:

```text
SPSS_INSTALL_PATH=C:\Program Files\IBM\SPSS Statistics\31
```

3. **Проверьте статус:**

```bash
spss-studio-mcp status
```

Ожидаемый вывод:

```text
=== SPSS MCP Capability Status ===
pyreadstat : OK v1.3.6
pandas     : OK v3.0.2
SPSS batch : OK
```

4. **Зарегистрируйте в `MCP/mcp_config.json`:**

```json
{
  "mcpServers": [
    {
      "name": "spss",
      "command": "spss-studio-mcp",
      "args": ["serve", "--transport", "stdio"],
      "env": {
        "SPSS_INSTALL_PATH": "C:\\Program Files\\IBM\\SPSS Statistics\\31"
      },
      "enabled": true
    }
  ]
}
```

### Если `SPSS batch: NOT FOUND`

Это значит, что `spss-studio-mcp` не нашёл движок SPSS, но `pyreadstat` + `pandas` работают. В этом случае Baize переходит в **файловый режим**:

- Можно читать `.sav`, смотреть метаданные, предпросматривать данные и конвертировать CSV ↔ SAV
- Нельзя запускать статистику: t-тесты, регрессию, ANOVA и т. д.

Решение: правильно задайте `SPSS_INSTALL_PATH` в `MCP/mcp_config.json` или примите переход в файловый режим.

## Интеграция SQL

### Поддерживаемые базы данных

PostgreSQL, MySQL, MariaDB, SQL Server, Oracle, DM, KingbaseES, TiDB, OceanBase и др. (на основе драйверов SQLAlchemy 2.0).

### Шаги настройки

1. **Подготовьте учётную запись базы данных только для чтения** (настоятельно рекомендуется):

```sql
CREATE USER baize_ro WITH PASSWORD 'xxx';
GRANT SELECT ON ALL TABLES IN SCHEMA public TO baize_ro;
```

2. **Подготовьте строку подключения:**

- PostgreSQL --> `postgresql+psycopg://user:pwd@host:5432/db`
- MySQL --> `mysql+pymysql://user:pwd@host:3306/db`
- SQL Server --> `mssql+pyodbc://user:pwd@host:1433/db?driver=ODBC+Driver+18+for+SQL+Server`
- Oracle --> `oracle+oracledb://user:pwd@host:1521/?service_name=ORCL`

3. **Зарегистрируйте в `MCP/mcp_config.json`:**

```json
{
  "mcpServers": [
    {
      "name": "sql",
      "command": "atengk-mcp-server-rdbms",
      "args": ["--transport", "stdio"],
      "env": {
        "DATABASE_URL": "postgresql+psycopg://baize_ro:pwd@localhost:5432/prod"
      },
      "enabled": true
    }
  ]
}
```

### Встроенные средства защиты

`atengk-mcp-server-rdbms` обеспечивает несколько уровней защиты:

- **SELECT-защита на уровне AST**: использует `sqlglot` для разбора синтаксического дерева и физически блокирует операции записи `DELETE/UPDATE/DROP/TRUNCATE`.
- **Автоматическое добавление LIMIT**: к запросам без указания количества строк принудительно добавляется `LIMIT 100`, что предотвращает выгрузку всей таблицы и переполнение памяти.
- **Только чтение по умолчанию**: операции записи требуют явного разрешения через `--allow-dml` / `--allow-ddl`.
- **Блокировка SQL-инъекций**: вредоносные инструкции, собранные конкатенацией строк, отклоняются на уровне AST.

### Настройка нескольких баз данных одновременно

Если нужно подключить несколько баз одновременно, зарегистрируйте несколько server:

```json
{
  "mcpServers": [
    {
      "name": "sql_prod",
      "command": "atengk-mcp-server-rdbms",
      "args": ["--transport", "stdio"],
      "env": { "DATABASE_URL": "postgresql+psycopg://ro:pwd@prod:5432/db" },
      "enabled": true
    },
    {
      "name": "sql_warehouse",
      "command": "atengk-mcp-server-rdbms",
      "args": ["--transport", "stdio"],
      "env": { "DATABASE_URL": "mysql+pymysql://ro:pwd@dw:3306/analytics" },
      "enabled": true
    }
  ]
}
```

Baize автоматически объединит все их инструменты в `MATERTOOLS`, и LLM выберет нужный в зависимости от задачи.

# Разработка

## Запуск тестов

Проект использует pytest. Перед разработкой установите пакет в редактируемом режиме с dev-зависимостями:

```bash
pip install -e ".[dev]"
```

Запуск всех тестов:

```bash
python -m pytest tests/ -v
```

Запуск одного файла:

```bash
python -m pytest tests/test_history.py -v
```

## Соглашения о структуре кода

- `agent/`: основной пакет, поставляемый вместе с дистрибутивом. Вся логика времени выполнения и ресурсы (skills, subagent, hooks, MCP) находятся здесь.
- `agent/core/`: модули чистой логики без внешних побочных эффектов. **Должны быть независимо тестируемыми.** Новую такую логику кладите сюда и добавляйте тесты.
- `tests/`: соответствие один-к-одному с исходниками в `agent/`, имена `test_<модуль>.py`.
- Любая функция с внешними зависимостями (сеть, диск, глобальное состояние) должна принимать их через параметры, чтобы их можно было подменять в тестах.

# ❓ FAQ

- В: Куда вводить API-ключ?

О: В `~/.baize/.env`, а не в `.env` корня проекта.

- В: Нужно ли переустанавливать при смене бэкенда?

О: Нет. Просто измените `active_provider` в `~/.baize/config.toml`.

- В: Требует ли локальный Ollama API-ключ?

О: Нет. Выберите `active_provider = "ollama"` и оставьте `env_key` пустым.

- В: Как переключить рабочую директорию?

О: Просто скажите «переключись на /path/to/project» — Baize вызовет инструмент `set_workspace`.

- В: Что произойдёт, если контекст станет слишком длинным?

О: Baize автоматически делает двухуровневое сжатие: сначала усекает старые результаты инструментов, затем просит LLM сгенерировать суммаризацию. Можно также вручную выполнить `/compact`.

- В: Может ли он случайно удалить мои файлы?

О: Белый список команд по умолчанию блокирует опасные операции вида `rm -rf /`; перед записью файла Baize показывает Diff и запрашивает подтверждение.

- В: Как подключить Baize к SPSS?

О: 1. Установите `pip install -r requirements-data.txt`; 2. Задайте переменную окружения `SPSS_INSTALL_PATH` на каталог SPSS; 3. Включите server spss в `MCP/mcp_config.json`. Подробнее см. раздел «Доступ к данным (SPSS / SQL)».

- В: Что делать, если появилось `SPSS batch: NOT FOUND`?

О: Это значит, что движок SPSS не найден. Проверьте, что `SPSS_INSTALL_PATH` указывает на каталог с `stats.exe`; если вы работаете только с `.sav`, можно игнорировать это предупреждение (файловый режим).

- В: Что ещё нужно установить для подключения к SQL?

О: На уровне Python установите `atengk-mcp-server-rdbms` (делается автоматически через `pip install`). **Пользователям SQL Server также нужно установить Microsoft ODBC Driver 18 на уровне системы**, это нельзя сделать через pip.

- В: Может ли Baize случайно удалить данные моей базы?

О: Нет. SQL MCP по умолчанию разрешает только SELECT, и все операции записи блокируются на уровне AST. Всё равно настоятельно рекомендуется создать отдельную **учётную запись только для чтения**.

- В: Могут ли данные из результатов SPSS утечь в LLM?

О: Если включено маскирование персональных данных (`/privacy on`), результаты инструментов автоматически маскируются (телефоны, email, удостоверения и т. п.) перед отправкой в LLM. **Но рекомендуется также использовать учётную запись только для чтения + выборку данных** (запрашивать только необходимые поля).

- В: Почему после добавления SPSS/SQL Baize работает медленнее и тратит больше токенов?

О: Потому что определения инструментов, предоставляемые MCP server, отправляются в LLM на каждом ходу диалога. У SPSS 60+ инструментов, что добавляет около 6000–12000 токенов фиксированных накладных расходов. Если ваш обычный рабочий процесс не использует SPSS, установите его `enabled` в `false` и включайте при необходимости.
