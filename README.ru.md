Байцзэ (Baize) — в древнекитайской мифологии благодатный зверь, который знает всё сущее, а теперь он воплотился в ассистента для Vibe Coding уровня предприятия.

**Открытый Coding Agent CLI с мощной защитой приватности и многоязычным взаимодействием. Поддерживает несколько бэкендов (DeepSeek / OpenAI-совместимые / GLM / Qwen / Kimi / локальный Ollama), а также вызов инструментов, загрузку навыков, делегирование подагентам, сжатие контекста и безопасную песочницу.**

----------

# Ключевые преимущества

## Защита приватности

- **Двунаправленная обратимая защита приватности**: перед отправкой в LLM ваша конфиденциальная информация заменяется плейсхолдерами, а после получения ответа автоматически восстанавливается. Весь процесс незаметен для вас — история, аргументы инструментов и финальный ответ, которые вы видите, всегда содержат исходный текст, а LLM видит только плейсхолдеры вроде `[[PHONE_1]]` и `[[EMAIL_1]]`.
- **Несколько способов включения защиты приватности**: можно включить естественным языком в диалоге или использовать более точную команду `/privacy`.
- **Локализация агента**: продукт не имеет удалённой базы данных и работает полностью локально. Он не собирает информацию о пользователе.

## Многоязычное взаимодействие

- **Поддержка девяти языков**: 中文, English, 日本語, 한국어, Español, Français, deutsch, русский, العربية.
- **Несколько способов переключения языка**: можно прямо сказать язык, например `please speak with english`, чтобы переключиться на английский, или использовать `/lang ja` для переключения на японский.

# Возможности

- **Поддержка нескольких бэкендов**: DeepSeek, любой OpenAI-совместимый API (GLM / Qwen / Kimi / OpenAI) и локальный Ollama. Переключение одной строкой.

- **Запуск без настройки**: при первом запуске конфигурационные файлы создаются автоматически. Ключ нужно ввести только один раз.

- **Маскирование персональных данных**: перед отправкой в LLM автоматически распознаются и заменяются на плейсхолдеры телефоны, email, номера удостоверений, банковские карты, API-ключи и другие PII; в ответе они восстанавливаются. Два уровня (стандартный / строгий), переключаются естественным языком или командой `/privacy`.

- **Многоязычное взаимодействие**: свободное переключение между китайским / английским / японским / корейским / испанским / французским / немецким / русским / арабским — достаточно сказать `English` или выполнить `/lang ja`, и ИИ будет думать и отвечать на этом языке.

- **Полный инструментарий**: выполнение bash-команд, чтение/запись/редактирование файлов, поиск glob/grep, веб-поиск и извлечение страниц, фоновые задачи, управление задачами и todo.

- **Система навыков (Skills)**: доменные знания (SKILL.md) загружаются по требованию — ИИ становится профессиональнее в конкретных сценариях.

- **Подагенты (Subagents)**: сложные задачи делегируются подагентам с независимым контекстом, что не загрязняет основную сессию.

- **Хуки (Hooks)**: хуки на Python или Shell для перехвата до/после вызова инструмента, ведения аудита, автоформатирования и «тестовых ворот».

- **Протокол MCP**: подключение внешних серверов инструментов (GitHub, Filesystem и др.) через Model Context Protocol.

- **Сжатие контекста**: двухуровневое сжатие (усечение старых результатов инструментов + суммаризация через LLM) для очень длинных диалогов.

- **Безопасная песочница**: белый список команд, детекция выхода за пределы рабочей директории, блокировка опасных команд, защита конфиденциальных файлов, перехват инъекций скриптов.

- **CLI в чёрно-золотой теме**: адаптивная ширина для китайского, подсветка кода, раскраска Diff, сворачивание размышлений.

# Быстрый старт

1. Первый запуск

bash

    baize

При первом запуске Baize автоматически создаёт два файла:

```
~/.baize/config.toml   # конфигурация бэкендов (DeepSeek / OpenAI / Ollama)

~/.baize/.env          # файл с ключами>
```

Путь в Windows: `C:\Users\ваше-имя\.baize\`.

2. Выбор бэкенда

Откройте `~/.baize/config.toml` и измените `active_provider`:

toml
```
active_provider = "deepseek"    # или "openai" / "ollama"

[model_providers.deepseek]
name = "DeepSeek"
base_url = "https://api.deepseek.com"
env_key = "DEEPSEEK_API_KEY"
model = "deepseek-v4-pro"

[model_providers.openai]
name = "OpenAI"
base_url = "https://api.openai.com/v1"
env_key = "OPENAI_API_KEY"
model = "gpt-4o-mini"

[model_providers.ollama]
name = "Ollama (local)"
base_url = "http://localhost:11434/v1"
env_key = ""
model = "qwen2.5:7b">
```

3. Ввод ключа

Отредактируйте `~/.baize/.env`:

env
```
# Обязательно для бэкенда DeepSeek

DEEPSEEK_API_KEY=sk-ваш-ключ


# Обязательно для OpenAI-совместимых API (GLM / Qwen / Kimi / OpenAI)

#OPENAI_API_KEY=ваш-ключ

#Локальный Ollama не требует ключа
```

4. Перезапуск

bash

    baize

Если вы видите чёрно-золотой логотип и приветствие — запуск прошёл успешно.

## Многоязычное взаимодействие

Baize поддерживает **девять языков**: 中文, English, 日本語, 한국어, Español, Français, deutsch, русский, العربية.

Переключение двумя способами:

### Способ 1: просто говорите (автоопределение)

Baize автоматически определяет язык ввода и переключается:

```
>>> 降旨：Привет, помоги написать скрипт на Python
[system] Обнаружен язык ввода: Русский. Baize переключился на Русский.
(отвечает по-русски)

>>> 降旨：Hello, write me a script
[system] Обнаружен язык ввода: English. Baize переключился на English.
(отвечает по-английски)
```

### Способ 2: команда вручную

```
>>> 降旨：/lang                # Показать текущий язык и список доступных
[system] Текущий язык: 中文 (zh)
[system] Доступные языки:
    zh    中文 ←
    en    English
    ja    日本語
    ko    한국어
    es    Español
    fr    Français
    de    Deutsch
    ru    Русский
    ar    العربية

>>> 降旨：/lang English        # Переключить по названию языка
>>> 降旨：/lang ja             # Переключить по коду языка
>>> 降旨：/lang 西班牙语        # Название по-китайски тоже работает

Поддерживается **название языка / код языка / китайское название / локализованное название**. Например, чтобы переключиться на английский, можно ввести `English`, `en`, `英语` или `英文`.

## Встроенные команды

- `/exit`, `/quit` --> Выйти из Baize
- `/clear` --> Очистить историю диалога, todo, записи размышлений и инструментов
- `/compact` --> Вручную сжать контекст (когда диалог слишком длинный)
- `/commit` --> Сохранить текущую сессию и закоммитить в Git (если внутри Git-репозитория)
- `/lang` → Показать текущий язык; `/lang en` переключает на английский (принимает код или название)
- `/skills` --> Список всех доступных навыков
- `/skills reload` --> Перезагрузить пользовательский каталог навыков
- `/unload` --> Выгрузить активный навык
- `/show thought` --> Показать полные записи размышлений
- `/show tool` --> Показать записи вызовов инструментов
- `/show all` --> Показать всю историю сессии
- `/имя-навыка` --> Загрузить указанный навык (с нечётким сопоставлением)
- `/privacy` --> Управление маскированием персональных данных (см. раздел «Маскирование персональных данных»)

# Механизмы расширения

Baize поддерживает четыре способа расширения. Достаточно разместить их в текущей рабочей директории.

## Навыки (Skills)

Пишите доменные знания в `./skills/имя-навыка/SKILL.md`. ИИ будет сам загружать их при сложных задачах.

markdown

    ---
    name: pandas-eda

    description: Лучшие практики разведочного анализа данных с pandas

    tags: data,python
    ---

    # Руководство по Pandas EDA

    ## Основные шаги
    1. df.info() — типы полей и пропуски
    2. df.describe() — описательная статистика
    ...

Также можно загрузить вручную командой `/pandas-eda`.

## Подагенты (Subagents)

Определите специализированных подагентов в `./subagent/роль/AGENT.md`. Главный агент может делегировать задачи через инструмент `agent`.

markdown

    ---
    name: code-reviewer

    description: Строгий ревьюер кода
    ---

    Вы — старший ревьюер кода. При ревью в первую очередь обращайте внимание на:
    1. Граничные условия и обработку ошибок
    2. Утечки ресурсов
    3. Потокобезопасность
    ...

## Хуки (Hooks)

Разместите в `./hooks/`:

- `PreToolUse-*.sh`
- `PostToolUse-*.sh`
- `Stop-*.sh`

Они получают JSON на вход и возвращают решение:

bash

    #!/bin/bash

    #PreToolUse-guard.sh

    read -r input

    if echo "$input" | grep -q "rm -rf"; then

    echo '{"hookSpecificOutput":{"permissionDecision":"block","permissionDecisionReason":"Удаление запрещено"}}'

    fi

Python-хуки могут напрямую вызывать встроенный API (см. функции `hook_*` в `Baize.py`).

## Серверы MCP

Настройте внешние серверы инструментов в `./MCP/mcp_config.json`:

json

    {
      "mcpServers": [
        {
          "name": "filesystem",
          "command": "npx",
          "args": ["-y", "@modelcontextprotocol/server-filesystem", "."],
          "env": {},
          "enabled": true
        }
      ]
    }

# Безопасность

По умолчанию Baize включает следующие механизмы:

- **Белый список команд**: разрешены только распространённые команды — `ls`, `cat`, `grep`, `git`, `python3` и т. п.
- **Детекция выхода за пределы**: все файловые операции ограничены текущей рабочей директорией и `/tmp`.
- **Блокировка опасных команд**: блокируются `rm -rf /`, fork-бомбы, `curl | sh`, `git push --force` и другие шаблоны.
- **Защита конфиденциальных файлов**: запрещено изменять `.env`, `.ssh/`, `id_rsa`, `*.pem` и т. п.
- **Перехват инъекций скриптов**: обнаружение обходов вида `python -c "os.system(...)"`.
- **Ограничение ресурсов процесса**: в Linux/macOS ограничиваются CPU, память и число процессов.

Если в доверенном проекте нужно ослабить ограничения, измените `ALLOWED_COMMANDS` и `FORBIDDEN_PATH_PATTERNS` в `Baize.py`.

# Маскирование персональных данных

Baize включает **двунаправленный обратимый** механизм маскирования персональных данных. Конфиденциальная информация заменяется плейсхолдерами перед отправкой в LLM и автоматически восстанавливается в ответе — полностью прозрачно для пользователя. Всё, что видите вы (история, аргументы инструментов, финальный ответ), всегда содержит исходный текст; всё, что видит LLM, — это `[[PHONE_1]]`, `[[EMAIL_1]]` и т. п.

**По умолчанию выключено.** Включается при необходимости.

## Два способа включения

### Способ 1: естественный язык

```
>>>降旨：включи маскирование персональных данных
[system] Маскирование персональных данных включено (стандартный режим).

>>>降旨：включи строгое маскирование
[system] Маскирование персональных данных включено (строгий режим).

>>>降旨：выключи защиту персональных данных
[system] Маскирование персональных данных выключено.
```

### Способ 2: слэш-команды

- `/privacy on` Включить стандартный режим
- `/privacy strict` Включить строгий режим (дополнительно: имена, номера машин, QQ, WeChat)
- `/privacy off` Выключить
- `/privacy status` Показать текущее состояние и статистику
- `/privacy rules` Вывести все правила
- `/privacy test` <текст> Протестировать маскирование
- `/privacy clear` Очистить карту плейсхолдеров

## Два уровня

**Стандартный**: мобильные номера материкового Китая, удостоверения личности, банковские карты (проверка Луна), email, IPv4/IPv6, ключи API OpenAI/Anthropic/GitHub/AWS, Bearer-токены, блоки приватных ключей, поля паролей, учётные данные в URL

**Строгий**: всё из стандартного + китайские имена, номера QQ, идентификаторы WeChat, автомобильные номера материкового Китая

## Как это работает

Ввод пользователя (с реальными PII) → сообщения хранят исходный текст

↓ sanitize_messages()

Что видит LLM: [[PHONE_1]], [[EMAIL_1]]

↓ ответ LLM

Плейсхолдеры → restore_message()

Восстановлено в оригинал → сохранение / отображение / выполнение

**Один и тот же исходный текст переиспользует один и тот же плейсхолдер**, поэтому один номер телефона остаётся `[[PHONE_1]]` на протяжении всей сессии.

**Аргументы инструментов различаются по чувствительности**: у чисто текстовых инструментов (`todo`, `ask_user_question`, `task_*`) аргументы маскируются; у инструментов, работающих с путями/командами/URL (`run_read`, `run_bash`, `run_webfetch`), они не трогаются — иначе выполнение провалится из-за подменённого пути.

**Подагенты также защищены**: задачи, делегированные главным агентом, проходят тот же конвейер маскирования и восстановления.

## Пример

```
>>>降旨：/privacy test Мой телефон 13812345678, email a@b.com
Исходный: Мой телефон 13812345678, email a@b.com
Маска   : Мой телефон [[PHONE_1]], email [[EMAIL_1]]
Восстан.: Мой телефон 13812345678, email a@b.com

>>>降旨：/privacy status
[Маскирование персональных данных]

# Разработка

## Запуск тестов

Проект использует pytest. Перед разработкой установите пакет в редактируемом режиме с dev-зависимостями:

    pip install -e ".[dev]"

Запуск всех тестов:

    python -m pytest tests/ -v

Запуск одного файла:

    python -m pytest tests/test_history.py -v

## Соглашения о структуре кода

- `agent/`: основной пакет, поставляемый вместе с дистрибутивом. Вся логика времени выполнения и ресурсы (skills, subagent, hooks, MCP) находятся здесь.
- `agent/core/`: модули чистой логики без внешних побочных эффектов. **Должны быть независимо тестируемыми.** Новую такую логику кладите сюда и добавляйте тесты.
- `tests/`: соответствие один-к-одному с исходниками в `agent/`, имена `test_<модуль>.py`.
- Любая функция с внешними зависимостями (сеть, диск, глобальное состояние) должна принимать их через параметры, чтобы их можно было подменять в тестах.

# ❓ FAQ

- В: Куда вводить API-ключ?

О: В `~/.baize/.env`, а не в `.env` корня проекта.

- В: Нужно ли переустанавливать при смене бэкенда?

О: Нет. Просто измените `active_provider` в `~/.baize/config.toml`.

- В: Требует ли локальный Ollama API-ключ?

О: Нет. Выберите `active_provider = "ollama"` и оставьте `env_key` пустым.

- В: Как переключить рабочую директорию?

О: Просто скажите «переключись на /path/to/project» — Baize вызовет инструмент `set_workspace`.

- В: Что произойдёт, если контекст станет слишком длинным?

О: Baize автоматически делает двухуровневое сжатие: сначала усекает старые результаты инструментов, затем просит LLM сгенерировать суммаризацию. Можно также вручную выполнить `/compact`.

- В: Может ли он случайно удалить мои файлы?

О: Белый список команд по умолчанию блокирует опасные операции вида `rm -rf /`; перед записью файла Baize показывает Diff и запрашивает подтверждение.

- В: Как заставить Baize отвечать на английском или японском?

О: Просто скажите `English` или `日本語`, и он переключится автоматически. Можно также использовать `/lang en` (или `/lang ja`). Всё последующее мышление и ответы будут на этом языке. Чтобы вернуться к китайскому, скажите `中文` или введите `/lang zh`.
